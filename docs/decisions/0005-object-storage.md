# ADR 0005: Object storage

## Status

Accepted

## Context

Evidence files need private object storage, opaque keys, and content hashes. The build plan starts with mocks and synthetic data. The storage API has to be chosen before ingestion work starts.

## Decision

Object storage uses the S3 API. Production buckets are private. Object keys are generated by the application, not taken from user paths.

Local development uses the S3 API through MinIO. Milestone 7.1 adds it to Compose. The community images on Docker Hub and `quay.io/minio/minio` no longer allow an anonymous pull, so Compose uses the public image `quay.io/minio/aistor/minio:RELEASE.2026-09-19T17-05-25Z`. While the S3 settings are empty, the API uses the mock store, including in tests.

## Consequences

- Evidence code will target the S3 API rather than a vendor-specific client surface.
- `.env.example` keeps the S3 settings empty until a developer is configuring MinIO or production storage.
- Public buckets and user-controlled object paths are out of policy.
