# Data model

Milestone 2.1 defines storage rules. Milestone 2.2 adds the first business tables. Milestone 2.3 adds server-side sessions. Milestone 2.4 enforces roles. The permission table is in [authorization.md](authorization.md).

## Identity and time

- Primary keys are `uuid` values generated by `uuidv7()`.
- Timestamps are `timestamptz`. The database and every API session use UTC.
- `created_at` is set once, with `clock_timestamp()`.
- `updated_at` is maintained by the `set_updated_at()` trigger, also with `clock_timestamp()`.

## Lifecycle and integrity

- Lifecycle states are PostgreSQL enum types or `CHECK` constraints created in a migration. Application code does not accept an unconstrained status string.
- Foreign keys name `ON DELETE` and `ON UPDATE`. Audit history uses `RESTRICT`. `CASCADE` is only for a child row that has no meaning without its parent.
- Records that can be updated concurrently include an integer `version` column, starting at 1. An update changes a row only when `version` still matches the value the caller read, and it sets `version = version + 1` in that same statement. `require_one_row` rejects a statement that did not change exactly one row.

## Transactions

A change that writes more than one record uses `transaction()`. That context commits every statement inside it, or rolls them all back. Callers do not issue a separate commit per row.

## Migrations

See [ADR 0008](decisions/0008-sql-migrations.md). `make migrate` applies `migrations/*.sql` in order. The bookkeeping table is `schema_migrations`.

## Tenancy

`users` are global identities. They store an email and an optional `oidc_subject`. The table does not store passwords, access tokens, or refresh tokens.

`auth_sessions` stores only the SHA-256 hash of the session cookie, an absolute `expires_at`, and an optional `revoked_at`. The raw token is returned once in an `HttpOnly` cookie. `oidc_login_attempts` stores the authorization-code flow, including the PKCE verifier, until the callback deletes that row. The flow is not returned to the browser.

Every other business table belongs to an `organizations` row. Project-scoped rows also store `project_id`, and the foreign key includes `organization_id`, so a row cannot point at a project in another organization. A project owner, project member, or task assignee must already be an active organization member.

`agent_definitions` belong to the organization. `agent_instances` belong to one project and pin `definition_revision`. `revision` is the definition's published version and increases when the definition changes. `version` on each mutable row is the optimistic-concurrency counter. `model_config_ref` is a configuration name. The API rejects secret material in a definition, and the row is not inserted. A database trigger rejects a new instance, or a start from any status other than `RUNNING` or `WAITING`, while the definition is `DISABLED`. Disabling a definition does not update existing instances.

## Tables

| --- | --- | --- |
| `organizations` | `slug` | Referenced rows block delete |

| `memberships` | organization + user | Restricted |
| `projects` | organization + `slug` | Restricted. Status `ARCHIVED` keeps history |
| `project_memberships` | project + user | Restricted |
| `agent_definitions` | organization + `agent_key` | Restricted. `model_config_ref` is a name, not a secret |
| `agent_instances` | row id | Restricted to the project and definition organization |
| `tasks` | row id | Restricted. Status includes `CANCELLED` |
| `task_dependencies` | task + predecessor | Restricted. Cycles and self-links are rejected |
| `workflow_runs` | project + `workflow_key` | Restricted. Optional task must be in the same project |
| `workflow_events` | row id | Immutable. Updates and deletes are rejected |
| `workflow_effects` | workflow run + operation key | Immutable. One outcome per operation |
| `model_calls` | row id | Immutable. Outcome, token counts, and cost only |
| `manager_plans` | row id | Immutable. Decision, assumption codes, and created task ids |
| `worker_results` | project + operation key, and task + result version | Immutable. Schema version 1. Proposed actions are not executed |
| `action_restrictions` | organization or project + action id | Restricted. A row denies that registered action |
| `approvals` | pending project + requester + payload hash | One decision. Parameters and hash stay bound. Execution status moves once from `NOT_STARTED` to `SUCCEEDED` or `REFUSED` |
| `action_executions` | project + payload hash | One recorded outcome. The row does not change |
| `mailbox_messages` | project + idempotency key | Immutable mock message. Status is `DRAFT` or `ACCEPTED`, never delivered |
| `mailbox_attachments` | project + attachment reference | Immutable metadata. Bytes live in an evidence file, not on this row |
| `evidence_files` | one inbound attachment | Immutable custody record. The object key is generated, and the hash is checked on download |
| `mock_objects` | object key | Immutable bytes for the mock store. Unused while S3 settings are set |
| `mailbox_notifications` | project + notification key | Immutable. A repeated key returns the first notice |
| `pbc_requests` | project + operation key | One evidence request. Status follows the transitions in [pbc.md](pbc.md). A change does not send email |
| `audit_events` | row id | Immutable. Updates, deletes, and truncates are rejected |
| `plan_procedures` | plan + phase + procedure key | Restricted. Removed with a reason, never deleted; a change revises the plan |
| `plan_versions` | plan + revision | Immutable. The plan's four sections as decided, with their SHA-256 hash |
| `plan_decisions` | row id | Immutable. Approved or changes requested, by whom, when, on which version |
| `auth_sessions` | `token_hash` | Restricted to the user. Expired and revoked rows do not authenticate |
| `oidc_login_attempts` | `state_hash` | Deleted when the callback consumes the attempt |

Task status values are `DRAFT`, `READY`, `QUEUED`, `RUNNING`, `WAITING`, `BLOCKED`, `REVIEW`, `SUCCEEDED`, `FAILED`, and `CANCELLED`. A save can follow only the transition allowed for the current status. `CANCELLED` stays in place until a reactivation operation returns it to `DRAFT`. `FAILED` can return to `READY` only through a retry operation, and only while `retry_count` is below `max_retries`. Moving to `BLOCKED` requires blocker text. Moving to `CANCELLED` requires a reason and sets `cancelled_at`. Dependency cycles and self-links are rejected by the database. A task cannot enter `QUEUED` or `RUNNING` while a predecessor is not `SUCCEEDED`. A worker crash before the effect row is written is recorded as `AMBIGUOUS`. A crash after the write keeps that one row. A new agent assignment is rejected when that definition is `DISABLED`. A workflow run starts as `RUNNING`. It can pause to `PAUSED` and resume to `RUNNING`. `RUNNING` and `PAUSED` can finish as `SUCCEEDED` or `FAILED`, or cancel to `CANCELLED`. Retry applies only to `FAILED`, increments `attempt`, and stops when `attempt` reaches `max_attempts`. Terminal statuses keep `finished_at`. Membership roles are `OWNER`, `ADMIN`, `PROJECT_MANAGER`, `REVIEWER`, and `CONTRIBUTOR`. Role checks live in the API authorization service, not in the session.
